# JourneyOffers 来源约定

此服务管理询价上下文领取、旅客航段引用及可比较资料接收。
当前常规业务使用一个选定来源上下文处理直接列出的记录。目录请求为 `GET /shopping/Q1`，返回 `query`、询价实际范围（`currency`、`passengers`、`segments`）与 `offers`。每个目录成员以 `id`、`href` 提供来源身份与原文位置，原文中的 `offer` 和 `query` 必须与目录一致。

## 记录含义

```json
{
  "offer": "O100",
  "query": "Q1",
  "currency": "CNY",
  "total": "1250.50",
  "segments": [
    "SHA-SIN",
    "SIN-SHA"
  ],
  "passengers": [
    "ADT1",
    "INF1"
  ],
  "expires": "2027-01-01T00:00:00Z"
}
```

这里的字段是来源提供的原始声明，数值文本必须符合十进制规则，不能把空白或未知值转换成零。领域解释保留询价内身份、旅客与航段列表、同报价价格冲突。只有所选范围内且有充分常规依据的记录列入当前收件；其他范围、待确认、历史和冲突分别保留结果，不用覆盖旧原文消除分歧。报价的币种、旅客与航段必须是询价实际范围的子集，越界报价按冲突保留，不悄悄替换比较人员正在看的报价。采集流程只读取证，不代替业务下单。

## 服务说明资料包

报价引用的服务资料分散在关联资料与服务说明中，且引用编号只在本次询价内有意义。目录在 `/shopping/{query}/relations/{offer}` 发布报价的关联资料，逐项把服务编号绑定到具体旅客与航段：

```json
{
  "query": "Q1",
  "offer": "O100",
  "services": [
    {
      "id": "S1",
      "kind": "baggage",
      "passengers": ["ADT1"],
      "segments": ["SHA-SIN"],
      "ref": "/shopping/Q1/services/S1"
    }
  ]
}
```

`kind` 取 `baggage`（行李）、`change`（改签）、`ancillary`（附加服务）。服务说明原文位于引用路径，携带自己的 `query`、`id`、`kind`、文字说明、可选金额与 `expires`：

```json
{
  "id": "S1",
  "query": "Q1",
  "kind": "baggage",
  "description": "成人去程免费托运一件二十三公斤",
  "amount": "0.00",
  "currency": "CNY",
  "expires": "2027-01-01T00:00:00Z"
}
```

适用范围规则：

- 引用必须落在本次询价自己的路径（`/shopping/{query}/...`）下。同一编号在另一次询价中即使文字与金额完全相同，也不是可复用的同一依据；服务说明原文声明的 `query` 不符时按冲突拒绝。
- 关联项只能引用报价自己声明过的旅客与航段。成人去程的托运行李不会被扩大解释给婴儿或回程；每个旅客×航段格独立核对，缺哪一格就逐格列出。
- 同一旅客×航段格内出现同类型但文字或金额不同的多份说明，属于报价内部引用互相冲突，保留全部原文而不是任选一份。
- 服务说明按 `expires` 与实际领取时间判断过期。三类说明都齐备但已过期时资料包为 `complete-expired`，与仍有缺格的 `incomplete` 分开报告。
- 同一服务编号在历次收件中出现不同原文时，新旧原文都保留并在资料包中标记 `reissued`，不静默复用旧说明。

资料包状态取四值：`complete`（询价矩阵三类说明齐备且未过期）、`complete-expired`（齐备但部分或全部过期）、`incomplete`（某些旅客或航段还缺说明）、`conflict`（引用越界、身份不符、说明互相冲突或关联资料无法取得）。每个资料包附带 `references`，逐项列出报价、关联资料与服务说明的询价归属和原文摘要，可逐项追到询价与引用集合。

## 部分航段重报

来源有时只肯通过重报部分航段提供已经过期的服务说明。此时来源给出的是另一份报价（新的报价身份或同一身份的不同原文）：系统为新报价单独建立资料包，按询价完整矩阵核对，未重报的航段自然显示为缺说明；原报价的总价、原文与历史资料包原样保留，不会把新税费塞进旧总价后称为原报价补齐。同一报价身份出现总价或币种不同的原文时，既有价格冲突规则继续生效。

## 本地合作源

`fixtures/source.json` 的 `resources` 是本地来源的 URL 路径到响应正文的映射；只绑定回环地址，不连接真实监管、银行或合作方。原文可通过目录声明的位置取得。`fixtureSource` 支持独立实例、指定路径返回码、一次性来源故障、响应延迟与 `replace` 更新资源；访问记录保留实际请求路径，不凭空生成未收到的响应。测试在进程内操作夹具，不提供对外开放的管理接口。目录不承诺所有关联资料与当前目录同时发布；HTTP 404、403、503 不能自行解释为业务删除，资料包会保留 `relations-unavailable` 或 `statement-unavailable` 冲突及原因。

## 原文和收件

原文字节按 SHA-256 寻址，SQLite 保存来源位置、观察时间、收件范围、业务身份、领域记录与决策。报价、关联资料、服务说明原文与资料包结论分别落库：服务说明按 `statement:{query}:{id}` 保留同一编号的每次不同原文，资料包按 `dossier:{query}:{offer}:{报价摘要}` 绑定到具体报价修订，资料包摘要由归档层对实际保管字节计算。收到原文不等于领域接收成功；重复的同一内容不新增收据，同一身份的不同内容不会覆盖原件。`.data/` 仅用于本机数据，演示使用临时目录，运行结束关闭服务并清理临时状态。

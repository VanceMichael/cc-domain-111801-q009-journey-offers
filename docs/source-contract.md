# JourneyOffers 来源约定

此服务管理询价上下文领取、旅客航段引用及可比较资料接收。
当前常规业务使用一个选定来源上下文处理直接列出的记录。目录请求为 `GET /shopping/Q1`，返回 `query` 与 `offers`。每个目录成员以 `id`、`href` 提供来源身份与原文位置，原文中的 `offer` 和 `query` 必须与目录一致。

## 询价范围与目录声明

服务资料采集以一次询价为边界。目录在 `query` 之外声明本次询价的实际范围：币种 `currency`、旅客组合 `passengers`、航段 `segments`；每个目录成员可通过 `relations` 声明该报价的服务引用位置（必须位于本次询价目录之下）。

```json
{
  "query": "Q9",
  "currency": "CNY",
  "passengers": ["ADT1", "INF1"],
  "segments": ["SHA-SIN", "SIN-SHA"],
  "offers": [
    { "id": "O200", "href": "/shopping/Q9/records/O200", "relations": "/shopping/Q9/relations/O200" }
  ]
}
```

报价按询价实际范围接收：币种不同、旅客或航段超出询价组合的报价判为范围外（`outside`），不计入资料包完成。

## 记录含义

```json
{
  "offer": "O100",
  "query": "Q1",
  "currency": "CNY",
  "total": "1250.50",
  "segments": ["SHA-SIN"],
  "passengers": ["ADT1"],
  "expires": "2027-01-01T00:00:00Z"
}
```

这里的字段是来源提供的原始声明，数值文本必须符合十进制规则，不能把空白或未知值转换成零。领域解释保留询价内身份、旅客与航段列表、同报价价格冲突。只有所选范围内且有充分常规依据的记录列入当前收件；其他范围、待确认、历史和冲突分别保留结果，不用覆盖旧原文消除分歧。

## 服务引用与服务说明

报价只保存来源对服务资料的**引用**，引用编号只在本次询价内有意义。服务引用资料（`relations`）按报价列出服务条目，`type` 只允许 `baggage`（行李）、`rebooking`（改签）、`ancillary`（附加服务），并声明各自适用的旅客与航段以及说明原文位置：

```json
{
  "query": "Q1",
  "offer": "O100",
  "services": [
    { "id": "S1", "type": "baggage", "passengers": ["ADT1"], "segments": ["SHA-SIN"], "ref": "/shopping/Q1/services/S1" }
  ]
}
```

服务说明原文必须回带 `query`、`service`、`type`、适用旅客、航段与有效期 `expires`。解释时强制核对：

- 说明的 `query` 必须等于报价所在询价。同一编号在另一次询价中即使文字和金额完全相同也不能复用，直接拒绝。
- 说明身份（编号、类型）与适用旅客、航段必须与引用一致；不一致属于报价内部引用冲突（`conflict`），保留两份原文，不挑一份覆盖另一份。
- 覆盖判定按声明的旅客×航段单元格精确核对：成人去程的托运行李不会扩给婴儿或回程。报价范围内未被任一有效说明覆盖的单元格逐项列为 `missing`。
- 同一服务编号出现互相矛盾的两条引用（位置或适用范围不同）判为 `conflict`；重复的相同引用不重复计数。

资料包整体状态优先级为 `conflict` > `missing` > `expired` > `complete`：

- `complete`：三类服务在报价范围内逐项齐备且未过期；
- `expired`：说明齐备但已过有效期（保留历史依据，可供比较人员知情）；
- `missing`：某些旅客或航段仍缺说明，或来源未发布/无权取得对应原文；
- `conflict`：报价内部的引用互相冲突。

每个资料包带 `trace`：询价号、报价号、服务引用摘要、引用集合与每条说明原文的 SHA-256 摘要和来源位置，可逐项追到询价和引用集合。

## 部分航段重报

来源有时只肯通过重报部分航段提供已经过期的服务说明。报价可用 `reissues` 声明它重报的原报价编号及涉及的旅客、航段：

```json
{
  "offer": "O203",
  "query": "Q9",
  "currency": "CNY",
  "total": "900.00",
  "passengers": ["ADT1"],
  "segments": ["SHA-SIN"],
  "reissues": [{ "offer": "O201", "passengers": ["ADT1"], "segments": ["SHA-SIN"] }]
}
```

重报的旅客与航段必须是原报价的**真子集**，否则判为冲突。合规重报作为**另一份报价**接收：独立总价、独立原文摘要，并在结果中注明原报价的历史依据与总价仍然保留；新税费绝不并入旧总价后称为原报价补齐。找不到原报价的重报声明同样判为冲突。

## 本地合作源

`fixtures/source.json` 的 `resources` 是本地来源的 URL 路径到响应正文的映射；`fixtures/service-package.json` 提供覆盖缺失、过期、冲突、部分重报与范围外的多报价询价。夹具只绑定回环地址，不连接真实监管、银行或合作方。原文可通过目录声明的位置取得。

`fixtureSource` 支持独立实例、指定路径返回码、一次性来源故障、响应延迟与 `replace` 更新资源；访问记录保留实际请求路径，不凭空生成未收到的响应。测试在进程内操作夹具，不提供对外开放的管理接口。目录不承诺所有关联资料与当前目录同时发布；HTTP 404、403、503 不能自行解释为业务删除，而是如实记录为该项资料取不到（`missing` 并附状态码原因）。

## 原文和收件

原文字节按 SHA-256 寻址，SQLite 保存来源位置、观察时间、收件范围、业务身份、领域记录与决策。报价原文、服务引用原文与服务说明原文各自落库，业务键按 `offer`、`relations:<报价>`、`service:<报价>:<类型:编号>` 区分。收到原文不等于领域接收成功；重复的同一内容不新增收据，同一身份的不同内容不会覆盖原件。`.data/` 仅用于本机数据，演示使用临时目录，运行结束关闭服务并清理临时状态。

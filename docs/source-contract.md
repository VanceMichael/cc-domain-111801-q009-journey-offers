# JourneyOffers 来源约定

此服务管理询价上下文领取、旅客航段引用及可比较资料接收。
当前常规业务使用一个选定来源上下文处理直接列出的记录。目录请求为 `GET /shopping/Q1`，返回 `query` 与 `offers`。每个目录成员以 `id`、`href` 提供来源身份与原文位置，原文中的 `offer` 和 `query` 必须与目录一致。

## 记录含义

```json
{
  "offer": "O100",
  "query": "Q1",
  "currency": "CNY",
  "total": "1250.50",
  "segments": [
    "SHA-SIN"
  ],
  "passengers": [
    "ADT1"
  ],
  "expires": "2027-01-01T00:00:00Z"
}
```

这里的字段是来源提供的原始声明，数值文本必须符合十进制规则，不能把空白或未知值转换成零。领域解释保留询价内身份、旅客与航段列表、同报价价格冲突。只有所选范围内且有充分常规依据的记录列入当前收件；其他范围、待确认、历史和冲突分别保留结果，不用覆盖旧原文消除分歧。

## 本地合作源

`fixtures/source.json` 的 `resources` 是本地来源的 URL 路径到响应正文的映射；只绑定回环地址，不连接真实监管、银行或合作方。原文可通过目录声明的位置取得。同一来源也可发布关联资料，当前示例的关联资料位置为 `/shopping/Q1/relations/O100`，字段保留来源的业务含义：

```json
{
  "services": [
    {
      "id": "S1",
      "passengers": [
        "ADT1"
      ],
      "segments": [
        "SHA-SIN"
      ],
      "ref": "/shopping/Q1/services/S1"
    }
  ]
}
```

`fixtureSource` 支持独立实例、指定路径返回码、一次性来源故障、响应延迟与 `replace` 更新资源；访问记录保留实际请求路径，不凭空生成未收到的响应。测试在进程内操作夹具，不提供对外开放的管理接口。目录不承诺所有关联资料与当前目录同时发布；HTTP 404、403、503 不能自行解释为业务删除。

## 原文和收件

原文字节按 SHA-256 寻址，SQLite 保存来源位置、观察时间、收件范围、业务身份、领域记录与决策。收到原文不等于领域接收成功；重复的同一内容不新增收据，同一身份的不同内容不会覆盖原件。`.data/` 仅用于本机数据，演示使用临时目录，运行结束关闭服务并清理临时状态。
